# Decision Log

프로젝트의 제품·기술 정책 결정을 기록한다.

## 승인된 결정

### 2026-07-11 — PDF 전체 페이지 판독 금지

- 상태: 승인
- 배경: 전체 문서를 읽으면 타 섹션 이미지·텍스트가 1섹션 또는 3섹션 결과로 오인입될 가능성이 높고 OCR·AI 비용도 불필요하게 증가한다.
- 검토한 선택지: 전체 문서 판독 / 전체 판독 후 필터링 / 섹션 한정 판독
- 결정: 디지털·이미지/OCR PDF 모두 전체 페이지 판독을 금지한다. 1섹션과 3섹션으로 확인된 페이지·영역만 처리하며, 경계를 확정하지 못하면 전체 판독으로 확대하지 않고 실패 또는 사용자 검토로 보낸다.
- 결정자: 사용자
- 코드·데이터 영향: 섹션 탐색, OCR, 이미지 크롭, AI 페이로드에 페이지·영역 제한이 강제되어야 한다.
- 검증 방법: 테스트 문서의 4섹션 이후 페이지가 OCR·AI 입력에 포함되지 않는지 호출 기록과 페이지 목록으로 확인한다.
- 재검토 조건: 없음.

### 2026-07-11 — 3섹션 구성성분명 추출 금지

- 상태: 승인
- 배경: 공식 명칭은 후단 공단 API가 CAS 번호를 기준으로 제공하므로 3섹션에서 이름을 추출·정제하는 작업은 비용과 정확도 자원을 낭비한다.
- 검토한 선택지: 이름·CAS·함유량 동시 추출 / 이름 참고 저장 / CAS·함유량만 추출
- 결정: 3섹션에서는 CAS 번호와 원문 함유량만 추출한다. 구성성분명은 추출·정제·복구·저장하지 않으며 이름으로 CAS를 추정하거나 생성하지 않는다.
- 결정자: 사용자
- 코드·데이터 영향: 3섹션 프롬프트와 결과 스키마에서 구성성분명 필드를 제외하고 후단 공단 API 매핑을 사용한다.
- 검증 방법: 3섹션 결과와 AI 응답 계약에 구성성분명 필드가 없고 `CAS(함유량)`만 전달되는지 확인한다.
- 재검토 조건: 공단 API 정책 또는 후단 데이터 계약이 변경될 때 사용자 승인 후 재검토한다.

### 2026-07-11 — 1섹션과 3섹션 AI 호출 분리 유지

- 상태: 승인
- 배경: 스캔 문서에서 제품명과 구성성분을 통합 원샷으로 요청하면 주의가 분산되어 미량 성분 누락과 제품명 오독이 발생할 수 있다.
- 검토한 선택지: 통합 원샷 1회 / 목적별 2회 / 문서별 조건부 통합
- 결정: 제품명과 구성성분을 기본적으로 별도 목적형 호출로 유지한다. 통합 원샷은 기본 최적화안으로 채택하지 않는다.
- 결정자: 사용자
- 코드·데이터 영향: 향후 AI 라우터와 프롬프트를 1섹션·3섹션 단위로 분리 유지한다.
- 검증 방법: 제품명 정확 일치, CAS 집합·순서, 함량 정확도, 미량 성분 누락률을 골든 데이터로 비교한다.
- 재검토 조건: 분리 호출과 동등한 정확도를 반복 검증으로 입증한 경우에만 재검토한다.

### 2026-07-11 — AI 충돌 시 사용자 검토 신호 적용

- 상태: 승인
- 배경: 서로 다른 추출기나 AI 모델이 충돌할 때 임의 자동 확정하면 False Green이 발생할 수 있다.
- 검토한 선택지: 한 모델 우선 자동 확정 / 다수결 / 신호등 강등 후 사용자 검토
- 결정: 충돌 결과는 자동 확정하지 않고 노란불로 표시한다. 완전성 실패나 근거 부재는 빨간불로 격리할 수 있다.
- 결정자: 사용자
- 코드·데이터 영향: 충돌 사유와 후보값을 결과 메타데이터에 남길 수 있어야 한다.
- 검증 방법: 의도적으로 충돌하는 테스트에서 초록불이 발생하지 않는지 확인한다.
- 재검토 조건: 없음. 세부 색상 임계값만 별도로 조정할 수 있다.

### 2026-07-11 — AI 호출 계측 도입

- 상태: 승인
- 배경: 공급자와 모델별 품질·비용·지연을 실제 데이터로 비교할 수단이 필요하다.
- 검토한 선택지: 총 호출 수만 기록 / 호출 단위 상세 계측
- 결정: 공급자, 모델 ID, 입력·출력 토큰, 시간, 재시도, 성공 여부, 추정 비용을 호출 단위로 계측한다.
- 결정자: 사용자
- 코드·데이터 영향: 공통 AI 호출 계측 구조와 민감정보 제외 정책이 필요하다.
- 검증 방법: 테스트 호출에서 필수 필드 기록, 비용 계산, 비밀키·원문 미기록을 확인한다.
- 재검토 조건: 공급자별 사용량 메타데이터 형식이나 가격 정책 변경 시 계산부를 갱신한다.

### 2026-07-11 — Vertex Flash-Lite 조건부 재평가

- 상태: 승인
- 배경: 과거 Flash-Lite 사용 시 호출 제한성 오류 경험이 있었으나 현재 호출 기반이 Vertex AI로 변경되어 운영 조건과 할당량 체계가 달라졌다.
- 검토한 선택지: 2.5 Flash 고정 / Flash-Lite 전면 교체 / 저위험 작업부터 조건부 적용
- 결정: `gemini-2.5-flash-lite` 안정판을 제품명과 단순 정제에서 우선 평가한다. 복잡한 3섹션과 저화질 스캔은 2.5 Flash를 유지하고, Lite가 완전성 게이트를 통과하지 못할 때 Flash로 승격한다.
- 결정자: 사용자
- 코드·데이터 영향: 작업 유형별 모델 라우팅, 재시도, 승격, 모델별 계측이 필요하다. 즉시 기본 모델을 교체하지는 않는다.
- 검증 방법: 정확도, JSON 유효성, 지연, 429·재시도율, 토큰, 비용, Flash 승격률을 동일 표본으로 비교한다.
- 재검토 조건: 대상 작업 통과율 95% 이상과 Flash 승격률 5~10% 이하를 초기 채택 후보 기준으로 검토하되, 최종 임계값은 표본 결과 후 확정한다.
