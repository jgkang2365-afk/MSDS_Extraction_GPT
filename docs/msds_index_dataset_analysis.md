# MSDS 측정인자 마스터 데이터셋 분석

## 1. 결론

`msds_index_V24.xlsx`는 297개 원본 행을 가진 유용한 측정인자 목록이지만, 현재 구조만으로는 CAS 후보 그룹, 최종 측정인자, 공정 추천, 추천 출처를 분리할 수 없다. 특히 동일 CAS 다중 그룹 45개(132행)가 존재하므로 CAS를 고유키로 쓰거나 최초 행만 채택하면 실제 측정인자 정보가 손실된다.

이번 단계에서는 운영 코드, MSDS 추출 엔진, VBA 및 xlsm을 변경하지 않았다. 확인한 원본을 기준으로 검토 CSV 4종과 스키마/구현 계획만 작성했다.

## 4. 자동 변환과 사람 검토

수치를 혼동하지 않도록 단계를 분리한다.

| 단계 | 자동 가능 | 사람 검토 | 기준 |
|---|---:|---:|---|
| 손실 없는 staging 적재 | 297행 | 0행 | 모든 원본 열, 시트·행 번호, 원문 값을 그대로 보존 |
| 측정인자 의미 자동 승인 | 164행 | 133행 | 동일 CAS 다중 132행 + 비표준 CAS 1행을 검토 대상으로 격리 |

동일 명칭 중복 2행은 동일 CAS 다중 132행에 이미 포함된다. `Unnamed: 25`는 열 단위 의미 검토 대상이지만 raw 보존이 가능하므로 133행 계산에는 중복 가산하지 않았다.

자동 변환은 “원본을 새 구조에 손실 없이 옮긴다”는 뜻이며, 부모·자식, form code, 공정 추천 또는 법적 의미를 자동 확정한다는 뜻이 아니다.

## 6. 대표 사례

### 알루미늄

- **확인**: CAS `7429-90-5`로 7행이며 정렬코드 `3M-20-140`~`3M-20-146`에 연속 배치되어 있다.
- **확인**: TWA가 10, 5, 2 ㎎/㎥로 갈린다.
- **판단**: 7행 모두 독립 `profile_id`를 받아야 한다. 최단 명칭을 부모로 자동 확정하지 말고 부모관계는 검토 후 입력한다.

### 크롬

- **확인**: CAS `7440-47-3`에 크롬/3가크롬/크롬광 가공 4행, CAS `18540-29-9`에 6가크롬 3행이 있다.
- **확인**: `SubstanceSelectDialog.__init__()`과 `find_mes_candidates()`가 크롬 후보에 6가크롬을 연결한다.
- **위험**: 현재 후보 목록에는 직접 검출과 공정 중 생성 추천의 출처 구분이 없다.
- **설계 요구**: 용접·고열·열절단 조건일 때만 `PROCESS_GENERATED` 추천을 만들고, `selection_source=process_recommended`, 사용자 확인, 복수선택 허용을 적용한다.

### 니켈

- **확인**: CAS `7440-02-0`에 5행, TWA 1/0.1/0.2 ㎎/㎥가 공존한다.
- **확인**: GUI는 일반 금속가공과 도금에 따라 불용성/수용성 후보를 안내한다.
- **판단**: 공정 추천은 규칙 데이터로 옮기되 기본 자동확정은 금지한다. 니켈카르보닐과 황화니켈류는 다른 CAS의 별도 인자이며 이름 계열만으로 연결하지 않는다.

### 실리카·탄산칼슘

- **확인**: 석영 CAS 셀은 `14808-60-7 등`으로 표준 CAS 형식이 아니다. 크리스토발라이트와 트리디마이트는 각각 별도 CAS다.
- **확인**: GUI는 `7631-86-9`, 결정형 실리카 CAS 3종, CAS 없는 기타광물성분진을 한 후보군에 넣는다.
- **확인**: `471-34-1`과 `1317-65-3`을 기타광물성분진으로 직접 치환하는 코드가 있다. 두 CAS는 V24 행에는 없다.
- **위험**: 순물질/합성 실리카/천연 광물 분진을 자동 동치로 처리할 수 없다.

### 활석·소우프스톤 검토 결정

- **사용자 제공 근거(2026-07-18)**: 안전보건공단 MSDS 조회 결과는 `활석[석면 불포함, 산화규소 결정체 1% 미만](호흡성)` TWA 2 mg/m³, `소우프스톤(호흡성)` TWA 3 mg/m³, 일반 `소우프스톤` TWA 6 mg/m³로 구분한다.
- **반영**: V24 `Sheet1!C15` 원본명 `소우프스톤`은 변환 canonical name을 `소우프스톤(호흡성)`으로 보정하는 검토 결정을 기록했다. 원본명은 lineage/raw 필드에 유지한다.
- **반영**: `활석(석면불포함)`과 `소우프스톤(호흡성)`은 같은 CAS라도 독립 selectable profile로 둔다.
- **주의**: 위 근거에는 일반 `소우프스톤` TWA 6 mg/m³도 별도로 있으므로 전체 그룹을 두 profile로만 축약하지 않는다. 일반 소우프스톤은 세 번째 독립 profile로 유지한다.
- **추가 검토**: V24의 일반명 `활석` 행은 `활석(석면불포함)`과 TWA·호흡성 분석방법이 같아 selectable 부모인지 중복 legacy 행인지 확인이 필요하다.
- **석면 관계**: 석면 포함 활석은 활석 profile로 자동 선택하지 않고 별도 `석면` profile을 `ANALYTICAL_RELATION`으로 추천하여 함유 여부를 사용자에게 확인한다.

## 7. 현재 GUI 연결 구조

### 확인된 흐름

1. `SMUGUI.load_mes_master()`가 `msds_index.json`을 리스트로 읽는다.
2. `mes_cas_map`은 동일 CAS 중 **최초 행 하나만** 보존한다.
3. 검증 흐름은 `msds_core.MSDSCore.validate_with_kosha()`가 CAS별 KOSHA/노출기준 정보를 `components`로 만든다.
4. GUI는 `msds_engine_v6.MES_MASTER_MAP` 또는 `mes_cas_map`으로 표준명을 덮어쓴다. `MES_MASTER_MAP`도 CAS당 문자열 하나다.
5. `find_mes_candidates()`가 CAS별 전체 V24 후보와 일부 교차 CAS 후보를 만든다.
6. 후보가 여러 개면 `SubstanceSelectDialog`와 `show_substance_selector()`가 정렬코드를 기준으로 복수선택을 저장한다.
7. `find_auto_twa_matched_candidate()`는 TWA 단일 일치 또는 규제문구의 “광물성분진”을 근거로 후보를 자동 선택한다.

### 구조적 결함

- `resolve_substance_variant()`는 `master_db[cas]["profiles"]` 구조를 기대하지만, 현재 저장소에서 `profiles`를 생성하는 코드는 확인되지 않았다.
- 선택 저장키가 `selected_code_{cas}`이며 profile 고유키가 아니다.
- `mes_cas_map`과 `MES_MASTER_MAP`은 CAS당 하나만 남겨 동일 CAS 세부 성상을 잃는다.
- `render_file_rows()`의 CAS 기준 중복 제거는 향후 동일 CAS 복수 profile 선택을 제거할 수 있다.
- 직접 검출, 동일 CAS 후보, 공정 추천, 수동 추가, 복원 선택이 동일한 후보/문자열 흐름에 섞여 있다.

하드코딩 18건의 위치·조건·이관 대상을 `data/review/2026-07-18_msds_index_review/gui_hardcoding_inventory.csv`에 정리했다.

## 8. VBA와 xlsm 참고 규칙

### xlsm 시트

| 기준목록 | A1:A290 | 명칭 정렬 기준 |
| 통합 유해인자 자료 | A1:Z274 | 분석방법·매체·정렬의 VBA 원본 |

### 정렬

- `Module1.리스트정렬()`: `기준목록`의 순서로 세미콜론 목록을 정렬하고 미등록 항목은 뒤에 유지하며 적색 표시한다. `ExtractBaseName()`은 마지막 괄호가 함량/미만 표시일 때만 제거한다.
- `Module3.공정별측정대상물질추출()`: 공정별 Dictionary로 물질을 중복 제거하고, 기준목록 순서 후 미등록 항목 가나다순으로 배치한다.
- `Module5.비고검토()`: 괄호 안 세미콜론 목록을 보호한 뒤 `통합 유해인자 자료` C열 순서로 정렬한다.
- `Module7.SortChemicals()`: `통합 유해인자 자료` 원본 행 순서를 물질 정렬 우선순위로 사용한다.

### 분석방법과 복수 물질 그룹화

- `Module7.측정계획자동화()`와 `매체_업데이트()`는 물질명을 분석방법으로 그룹화하고 고정된 분석방법 우선순위 배열로 정렬한다.
- 분석방법에 `(단)`이 있으면 물질별 개별 행을 만들고, 그 외에는 같은 방법의 물질을 한 행에 세미콜론으로 묶는다.
- `(다)` 분석방법인데 그룹에 물질이 하나뿐이면 출력명을 `(단)`으로 바꾼다.
- 그룹 대표 매체/유속은 첫 번째로 정렬된 물질의 값을 사용한다.
- 분석방법이 없는 항목은 별도 구역에 적색으로 출력한다.

### 특별관리·허가·특검 표시

- `Module5.비고검토()`는 52개 특별 유해인자 명칭 배열을 코드에 보유하고 정확히 일치하면 청색 표시한다.
- 이 로직은 명칭 강조용이며, V24의 `허가대상`, `특별관리`, `특검` 열을 판정하는 일반 규칙으로 확인되지는 않았다.
- 따라서 VBA의 청색 목록을 법적 분류의 진실 공급원으로 승격하면 안 되며 참고 근거로만 보존해야 한다.

### 동일 공정 내 중복 제거와 예외 그룹

- `Module3`과 `Module7`은 공정명별 Dictionary 키로 동일 문자열 물질을 중복 제거한다.
- `Module7.ProcessSpecialPatterns()`는 `단시간 및 임시작업`, `보관`, `허용소비량 미만`, `특별관리물질` 괄호 안 세미콜론을 임시 보호한다.
- `Module7.FormatGroupedChems()`는 위 예외 카테고리별로 물질을 다시 묶고 중복 제거한다.
- 이는 문자열 단위 중복 제거이며 profile 식별자 기반 중복 제거가 아니다.

## 10. 현재 데이터로 표현 불가능한 사례

- MSDS 직접 검출과 공정 추천의 출처 분리
- 같은 CAS의 여러 profile과 안정적 profile ID
- 부모·자식 관계의 명시적 승인 상태
- 서로 다른 CAS의 공정 중 생성/동반노출/대체/분석 관계
- 조건 조합(용접 AND 고열, 특정 형태 제외 등)
- 추천 강도, 기본 선택 여부, 복수 선택 허용, 사용자 확인 필요 여부
- 별칭이 부모 그룹을 가리키는지 특정 profile을 가리키는지 구분
- 법적 분류 및 분석조건의 근거 버전과 검토 이력
- 원본 V24 행과 변환 profile 간 추적성
- CAS 없는 측정인자의 안정적 식별

## 11. 데이터 품질 문제와 위험

- `msds_index.json`은 296행으로 V24 297행과 이미 행 수가 다르다. 정렬코드 대조 결과 V24 `Sheet1!A83`의 `3M-20-212`(`3가크롬`, CAS `7440-47-3`)이 JSON에서 누락되어 있다. 생성 경로와 누락 원인을 별도 검증해야 한다.
- CAS `14808-60-7 등`은 CAS 검색키로 직접 사용할 수 없다.
- 동일 명칭 `소우프스톤`이 같은 CAS에 서로 다른 정렬코드·분석방법·TWA로 두 번 존재한다.
- 같은 CAS 안에서 단위/노출기준/매체/법적 표시가 달라 CAS 단일 맵으로 축약할 수 없다.
- 최단 명칭을 부모로 간주하거나 괄호만으로 성상을 확정하면 이명과 규제조건을 오판할 수 있다.
- TWA 숫자만 비교하면 ppm과 ㎎/㎥ 또는 서로 다른 성상을 잘못 매칭할 수 있다.
- VBA 분석방법 그룹에서 첫 물질의 매체·유속을 대표값으로 쓰므로 그룹 내 조건 불일치를 사전에 검사해야 한다.
- 정렬코드 변경이 profile ID 변경으로 이어지면 저장된 사용자 선택과 향후 엑셀 출력이 깨진다.

## 12. 코드 수정 전 권고

1. 297행을 그대로 staging에 적재하고 `source_sheet`, `source_row_number`, `source_row_id`, 모든 raw 값을 보존한다.
2. 동일 CAS 132행과 비표준 CAS 1행을 먼저 검토한다.
3. 최초 `profile_id`를 한 번 발급하여 관리 원본 Excel에 영구 저장한다.
4. 4개 데이터 층과 검토상태가 승인된 뒤 resolver를 구현한다.
5. 기존 GUI에는 adapter만 추가하고, 추출 엔진과 VBA는 이 단계에서 변경하지 않는다.
