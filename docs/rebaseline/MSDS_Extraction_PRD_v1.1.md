# MSDS 추출 시스템 재기준화 PRD v1.1

**문서 ID:** MSDS-PRD-001
**버전:** v1.1 보완본
**문서 상태:** 최종 승인 대기
**작성일:** 2026-09-06 (한국시간)
**대상:** MSDS_Extraction_GPT
**후속 문서:** TRD v1.0 → 버전·차수가 명시된 실행 작업지시서

이 문서는 대화에서 승인한 재기준화 방향·업무 정책·목표 구조와 PRD v1.0 검토 보완사항을 통합한 제품 요구사항 문서다. 코드 구현, 저장소 반영, 성능 실측 또는 운영 전환 완료를 의미하지 않는다. v1.1이 승인되면 PRD v1.0을 대체한다.

## 1. 목적과 성공의 정의

본 시스템의 1차 목적은 국가·언어·제조사·문서 양식·표기 방식이 서로 다른 MSDS PDF에서 **1항의 제품명**과 **3항의 CAS 번호 및 각 CAS에 대응하는 함유량**만 정확하게 추출하는 것이다.

3항의 구성성분명·화학물질명은 1차 추출 결과 대상에 포함하지 않는다. 2항·8항·15항 등 다른 항의 내용을 읽어 제품명·CAS·함유량을 보완하는 것도 1차 추출 범위에 포함하지 않는다.

성공은 일부 값을 맞히거나 결과를 많이 만드는 것이 아니다. 원본의 허용된 영역에서 대상 정보를 빠짐없이 처리하고, 판독값·정규화값·근거를 보존하며, 확정할 수 없는 결과는 정상 결과와 구분하는 것이다. 자동 확정 정확도와 자동 처리 비율을 함께 평가하여 모든 어려운 문서를 REVIEW로 보내는 방식만으로 성공을 선언하지 않는다.

재기준화의 목적은 기존 실전 경험을 버리는 것이 아니라 **업무 기준, 판독 수단, 운영 정책, 과거 장애 기록을 분리하여 반복 수정으로 인한 회귀를 줄이는 것**이다. 기존 코드의 실제 결함 여부와 현재 성능은 별도의 코드·실행 검증으로 판단한다.

## 2. 범위와 보류 과제

### 2.1 이번 재기준화에 포함

| 영역 | 이번 범위 |
|---|---|
| 핵심 추출 | 1항 제품명, 3항 CAS↔함유량, 해당 항의 경계 격리 |
| 문서 처리 | 디지털·스캔 경로, 대상 영역별 혼합형 대응, 필요한 경우에만 OCR·AI 사용 |
| 품질 관리 | 근거 연결, 후보 검증, 문서 전체 누락 의심 판정, PASS/REVIEW 구분 |
| 사용자 보완 | 기존 수정 기능 활용, 기계 결과와 교정값 분리, 재처리·저장 시 교정값 보호 |
| 검증 자산 | 기존 Golden 재검증, Golden v2 및 검토 필요 사례군, 최종 평가 자료군 |
| 후단 연동 | 기존 KOSHA/MES 업무 기능 보존, KOSHA 조회 성능 재검증 및 비동기 후단 분리 |
| 점진 전환 | 기존 운영 버전 보존, 신구 결과 차이 분석, 단계별 검증·전환 |

### 2.2 이번 범위에 포함하지 않음

MSDS 다른 항의 범용 추출, 제조사 MSDS의 오류 자동 수정, 물질명으로 CAS 추론, 모든 국가·양식의 하드코딩 지원, MES 규칙의 전면 재설계, 대규모 GUI 재설계 및 별도 수정 프로그램 신설은 이번 기본 범위에 포함하지 않는다.

### 2.3 명시적으로 보류한 과제

**KOSHA 전체 Local Chemical Master 구축, CSV/JSON/Bulk 일괄 데이터 확보, 2항·8항 정보 확장 및 전체 로컬 동기화 체계는 보류한다.** 기존 KOSHA 성능 측정·캐시 검토·비동기 분리는 이번 범위다. 보류 과제를 구현 편의나 선행조건이라는 이유로 자동 편입하지 않는다.

## 3. 문서 권위와 변경 관리

**GOV-01 — 기준의 우선순위.** 승인된 최신 PRD가 제품 동작의 기준이다. 사용자 승인 변경사항은 변경 이력과 영향 범위를 기록한 뒤 PRD에 반영한다. TRD·작업지시서·기존 Rulebook/DNA·코드 주석이 PRD와 충돌하면 구현자가 임의로 절충하지 않고 충돌을 보고한다. 과거 해결책을 자동으로 현행 정책으로 승격하지 않는다.

**GOV-02 — 역할 분리.** PRD는 정답 범위, 허용·금지 동작, 보존 대상, 품질·운영 요구 및 완료 기준을 정의한다. TRD는 이를 구현할 모듈·스키마·상태 전이·알고리즘·설정·테스트 구조를 정의한다. PRD 작성·승인은 곧바로 코드 변경이나 운영 배포를 승인하는 것이 아니다.

**GOV-03 — 추적 가능성.** 본문의 요구사항 ID는 TRD 설계 항목과 검증 사례에 연결한다. 요구사항을 변경할 때는 변경 사유, 사용자 승인 여부, 영향을 받는 데이터·기존 기능·테스트를 기록한다. 문서 상태명과 예시 필드명은 상세 스키마가 아니며, TRD에서 대응 관계를 유지한 채 구체화할 수 있다.

## 4. 사용자와 업무 흐름

주 사용자는 현장에서 수집한 다양한 MSDS를 업무 데이터로 정리하고 확인·수정하여 후속 업무에 사용하는 담당자다. 검토자는 원본 PDF를 보고 불확실한 판독 결과를 바로잡고, 별도 절차로 Golden 후보를 승인할 수 있다.

기본 흐름은 **파일 입력 → 대상 영역 분류·격리 → 판독·매칭 → 기계 결과 표시 → 자동 품질 판정 → 필요한 부분만 사용자 보완 → 업무용 결과 확정 → KOSHA/MES 보강 → 표시·내보내기**다.

자동 PASS 결과는 별도 수동 승인 버튼을 반드시 누르게 하지 않고 후속 업무에 사용할 수 있다. 다만 자동 검증과 사람의 원본 확인 이력은 구분한다. KOSHA 조회를 기다리는 동안에도 추출 결과 확인과 사용자 보완은 가능해야 한다.

## 5. 입력과 문서 유형

**IN-01 — 대상 영역별 처리.** 최초 문서 분류는 OCR 모델을 로딩하지 않는 가벼운 PDF 분석으로 수행한다. 이후 1항·3항 각각에서 텍스트의 이용 가능성과 판독 품질을 확인한다. 파일에 텍스트가 있다는 이유만으로 모든 영역을 디지털로 처리하거나, 로고·그림이 있다는 이유만으로 OCR을 실행하지 않는다. 디지털과 이미지가 혼합된 문서는 필요한 영역만 스캔 경로로 처리한다.

**IN-02 — 처리 불가 입력의 격리.** 손상·열기 실패·비MSDS 입력·처리 권한을 확보하지 못한 암호화 PDF·여러 MSDS가 합쳐진 것으로 의심되는 입력은 이유를 표시한다. 1차 범위에서 문서 분리 또는 해독을 자동 구현하지 않으며, 지원하지 못하는 입력을 정상적인 성분 0건으로 처리하지 않는다. 한 파일의 실패가 나머지 파일 처리를 막지 않아야 한다.

**IN-03 — 원본의 식별과 보호.** 파일명과 별도로 원본 PDF의 SHA-256 및 실행 식별정보로 결과를 연결한다. 파일명 변경은 정답을 바꾸는 근거가 아니며, 동일 파일명의 다른 바이트 내용은 다른 원본으로 취급한다. PDF 원본은 판독·정규화·검증 과정에서 수정하지 않는다.

## 6. Section Fence: 1항·3항의 입력 격리

**FNC-01 — 값 추출 이전 격리.** 제품명 판독기는 확정된 1항, CAS·함유량 판독기는 확정된 3항의 내용만 입력으로 받는다. 같은 페이지에 있는 다른 항, 머리말·꼬리말 등 해당 항 밖의 정보가 추출 근거로 들어가지 않도록 논리적 범위와 전달 텍스트·이미지의 범위를 함께 제한한다. 프롬프트로 “다른 항을 무시하라”고 지시하는 것만으로 격리를 대신하지 않는다.

**FNC-02 — 정찰 권한과 자료 재사용.** 전체 문서는 항의 위치·경계를 탐색하는 데 사용할 수 있지만, 정찰 단계에는 제품명·CAS·함유량을 최종 확정할 권한이 없다. Fence 확정 후 그 내부로 제한한 정찰 판독 자료는 추출 단계의 입력으로 재사용할 수 있다. 이 경우에도 후보 생성·매칭·검증 절차를 거쳐야 하며, 정찰 결과의 직접 승격은 금지한다. 재사용만을 이유로 동일 영역을 무조건 다시 OCR하지 않는다.

**FNC-03 — 여러 페이지와 이어지는 표.** 1항은 원칙적으로 2항 시작 전까지, 3항은 원칙적으로 4항 시작 전까지의 논리적 영역이다. 동등한 구조적 종료 근거를 사용하는 경우 그 근거를 남긴다. 3항이 여러 페이지에 걸치면 하나의 연속 영역으로 처리하고, 이어지는 행·표제·공통 함유량 관계를 보존한다. 고정 페이지 수를 정답 영역의 종료 조건으로 사용하지 않는다.

**FNC-04 — 경계 불확실 시 차단.** 경계 상태는 CONFIRMED, PARTIAL, NOT_FOUND를 구분한다. 불확실하면 허용된 시간·비용 내에서 위치 탐색을 재시도하되, 그 상태로 추출기에 전체 페이지·문서를 전달하여 값을 확정하지 않는다. 한도에 도달하면 경계 미확정 사유와 처리 상태를 남긴다. 자원 상한은 실행 중단 조건이며 “3항을 전부 확인했다”는 근거가 아니다.

**FNC-05 — 항별 독립 보존.** 1항 실패가 정상적으로 처리한 3항의 결과를 삭제하게 해서는 안 되며, 그 반대도 동일하다. 항별·필드별 결과와 문서 전체 판정을 구분한다. 확인된 부분을 보존하더라도 문서 전체 자동 PASS 조건은 별도로 충족해야 한다.

## 7. 제품명 추출

**PN-01 — 정답 출처와 문자 보존.** 제품명은 1항의 실제 표기만을 근거로 한다. 파일명·3항 물질명·제조사명·다른 항·외부 DB로 대체하거나 추론하지 않는다. 제품 식별에 포함된 모델번호·등급·농도·괄호·기호·대소문자·언어 표기는 임의 삭제·번역·제목형 변환을 하지 않는다. 비교용 문자열 정규화와 사용자에게 제공할 제품명은 구분한다.

**PN-02 — 로컬 확정 조건.** 로컬 확정은 Fence 확인, 1항 내부 출처, 제품명 레이블과 값의 직접적인 행·셀·블록 관계, 회사·주소·용도 등과의 구분, 강한 경쟁 후보 부재, 텍스트와 배치의 비모순을 함께 확인한 경우로 제한한다. 점수 하나나 “틀렸다는 증거가 없음”만으로 확정하지 않는다. 판정 근거를 기록하고 LOCAL_CONFIRMED와 LOCAL_UNCERTAIN을 구분한다.

**PN-03 — 제한된 AI 보조.** 후보 부재·경쟁·레이블 연결 불명확·낯선 표기·읽기 순서 이상 등으로 로컬이 확정하지 못하면 같은 1항 Fence만 AI에 전달할 수 있다. AI가 실제 표기와의 연결을 확인할 수 있는 후보를 반환하도록 하며, AI의 자기평가나 로컬과의 단순 일치만으로 원문 확인을 대신하지 않는다. 구체적인 엔진과 판정 기준은 대표 자료의 검증으로 정한다.

**PN-04 — 미확인 상태.** 1항 안의 제품명 부재, 표기는 있으나 판독 불가, 후보 충돌, 1항 경계 미확정을 구분한다. 확정 제품명은 공란 또는 미확정 상태로 유지하고 검토용 후보를 별도로 보존한다. 미확인 제품명 때문에 정상 CAS·함유량을 버리거나 파일명으로 채우지 않는다.

## 8. 3항 CAS 중심 추출과 매칭

**CAS-01 — 포함·제외 규칙.** 3항에서는 CAS를 기준으로 함유량을 매칭한다. CAS가 없으면 함유량이 있어도 최종 성분 결과에서 제외한다. CAS가 원문에서 확인되면 함유량이 없더라도 유지한다. CAS 미확인·검증 실패 후보는 검토 자료로 남길 수 있지만 정상 CAS 결과나 후단 자동조회 대상으로 승격하지 않는다.

| 원문의 상태 | 최종 추출 처리 |
|---|---|
| CAS 있음 + 대응 함유량 있음 | CAS와 함유량을 함께 유지 |
| CAS 있음 + 함유량 실제 미기재 | CAS 유지, 함유량 NOT_STATED |
| CAS 있음 + 함유량 판독·매칭 불확실 | CAS 유지, 함유량 미확정 및 REVIEW |
| CAS 없음 + 함유량 있음 | 성분 결과에서 제외; 이 함유량을 이웃 CAS에 넘기지 않음 |
| 물질명만 있음 | 성분 결과에서 제외 |

**CAS-02 — 체크디지트의 제한된 역할.** 체크디지트는 주변 숫자가 섞이거나 OCR·조립이 잘못된 CAS 후보를 검출하는 장치다. 통과 자체가 해당 위치에 그 CAS가 존재한다는 증명은 아니다. 실패하면 같은 3항의 관련 행·셀·블록 증거로 재조립·재판독한다. 다른 항·외부 DB의 유사 CAS로 자동 치환하지 않는다. 해결되지 않은 후보는 REVIEW로 남긴다.

**CAS-03 — 원문 중복과 판독기 중복.** 서로 다른 원문 행에 동일 CAS가 반복되면 순서와 각 함유량을 그대로 보존하고 임의 합산·병합하지 않는다. 반면 동일한 원문 기재를 여러 판독기가 읽은 경우 최종 결과를 여러 행으로 늘리지 않고 하나의 원문 기재에 복수 후보·근거를 연결한다. CAS 값만을 결과의 유일한 행 식별자로 삼지 않는다.

**CAS-04 — 복수 CAS와 공통 함유량.** 하나의 원문 성분 묶음에서 여러 줄의 CAS에 하나의 함유량이 공통 적용된다는 관계가 확인되면 해당 함유량을 각 CAS에 동일하게 적용한다. CAS별 독립 결과와 공유 근거를 함께 유지한다. 같은 Crop·가까운 좌표라는 이유만으로 공통 함유량을 추정하지 않는다. 범위가 불분명하면 PAIR_AMBIGUOUS로 처리한다.

**CAS-05 — 구조 해석과 물질명 추론의 구분.** 구성성분명 자체는 추출 결과로 만들거나 정답 판정의 요구 필드로 삼지 않는다. 다만 주변 글자의 배치와 레이블을 표·행·블록 경계 파악에 사용하는 것은 허용한다. 물질명에 들어 있는 숫자·농도·식별번호를 해당 행의 CAS 또는 함유량으로 오인하지 않아야 한다. 성분명을 보고 CAS·함유량을 생성하거나 삭제하지 않는다.

## 9. 함유량 상태·정규화·단위

**CON-01 — 상태의 의미.** FOUND, NOT_STATED, NOT_READABLE, PAIR_AMBIGUOUS를 구분한다. 아직 대응 위치를 찾지 못한 것은 미해결 상태이며 NOT_STATED가 아니다. `미기재%`는 NOT_STATED의 표시 문구일 뿐 최초 판독값이나 수치 데이터가 아니다. 다른 미확정 상태에는 판독 불가·매칭 확인 필요 등 구분된 안내를 사용한다.

**CON-02 — 부재 확인.** NOT_STATED는 대응 영역을 확인해 함유량이 실제로 없음을 판단한 경우만 사용한다. OCR이 숫자를 반환하지 않았거나 시간이 부족했다는 이유로 미기재를 확정하지 않는다. 판단에 필요한 영역이 읽히지 않으면 재판독 또는 REVIEW로 처리한다.

**CON-03 — 의미 보존 정규화.** 공백·전각·동등한 기호 등 표기 통일만 허용한다. `<`, `>`, `≤`, `≥`, 범위 끝점의 포함 여부와 원문 수치를 보존한다. 특정 경계값에만 부등호를 남기거나 범위를 단일값으로 축약하지 않는다. 역순 표기는 같은 구간을 뜻한다는 구조가 명확한 경우에만 표시 순서를 정리하고 근거를 남기며, 불명확한 수식을 단순 숫자 정렬로 수정하지 않는다.

**CON-04 — 단위의 근거.** `%` 보완은 해당 열·표제·블록에서 백분율 단위가 확인된 경우만 허용한다. ppm·질량 단위·단위 불명을 임의로 `%`로 바꾸지 않는다. wt%·vol% 등 원문이 구분한 기준도 보존한다. 별도 업무 변환은 원문 단위와 추출값을 덮어쓰지 않는 후단 기능이며 이번 기본 추출에서 자동 단위 환산을 수행하지 않는다.

**CON-05 — 이상한 원문과 잔량.** 100% 초과·범위 상한 합계 이상을 이유로 판독값을 삭제하거나 미기재로 바꾸지 않는다. 원문이 명확하면 추출 자체는 정상일 수 있고 별도 경고로 구분한다. 잔량·Balance·Rem.은 실제 표기된 정성값으로 보존하고, 다른 성분의 합계를 빼 수치로 채우지 않는다. 서로 다른 등급·조건의 함유량을 근거 없이 하나로 축약하지 않는다.

| 원문 또는 상태 예시 | 허용되는 처리 예시 |
|---|---|
| 0.1 이상 ~ 1 미만, 백분율 열 | ≥0.1~<1%로 표기; 최초 판독값 별도 보존 |
| 70 이상 ~ 75 미만 | ≥70~<75%; 미만 기호 삭제 금지 |
| 98.5~101.5% | 값 유지; 필요 시 수치 이상 경고 |
| 100 ppm | 100 ppm 유지; 100%로 변경 금지 |
| 잔량 | 잔량 의미 유지; 계산값 생성 금지 |
| 숫자 표기는 있으나 읽지 못함 | NOT_READABLE; 미기재% 표시 금지 |

예시는 정책 설명용이며 특정 PDF의 실제 추출 정답이나 성능 증거를 뜻하지 않는다.

## 10. 원본 증거와 내부 데이터 계약

**DAT-01 — 원본·판독·정규화의 분리.** 원본 증거는 변경하지 않은 PDF 및 그 안의 위치다. raw는 판독기가 반환한 정규화 전 최초 판독값을 뜻하며, 항상 원본과 일치한다는 보장이 아니다. 예를 들어 OCR raw가 `10~30%`여도 원본은 `10~20%`일 수 있다. 원본 증거, 최초 판독값, 정규화값, 채택·기각 사유를 구분한다.

**DAT-02 — 구조화와 행 정체성.** 내부 주요 업무 데이터는 제품명과 순서 있는 CAS↔함유량 기재 목록으로 유지한다. 각 기재에는 상태와 근거가 연결되어야 한다. `CAS(함유량); …` 문자열을 중간 데이터 계약으로 사용하거나 이를 반복 파싱하지 않는다. 기존 경로와의 호환 변환이 필요하면 경계를 한정하고 손실 가능성을 명시한다.

**DAT-03 — 추적 가능한 근거.** 결과에서 원본 해시, 실제 페이지, 해당 Fence와 관련 행·셀·블록 또는 식별 가능한 영역을 되짚을 수 있어야 한다. 같은 영역 안의 서로 다른 기재를 구분할 수 있어야 하며, 페이지 번호를 일괄 기본값으로 채우지 않는다. 스캔본은 판독 문자열만이 아니라 이미지 원본 위치를 확인할 수 있어야 한다. 좌표 등 상세 표현은 TRD에서 정한다.

**DAT-04 — 실행·버전 이력.** 결과에 실행, 엔진·업무 정책·정규화·사용한 판독 모델 및 관련 프롬프트 버전을 추적할 수 있는 정보를 남긴다. 새 판독·정규화·수동 수정이 생겨도 이전 Machine Result를 덮어쓰지 않는다. 로그를 보존하는 것만으로 원본·기계 결과·사용자 교정 데이터의 보존을 대체하지 않는다.

## 11. 로컬·OCR·AI 사용과 실행 자원

**RUN-01 — 필요한 경우에만 OCR 로딩.** 1항·3항 및 필요한 경계 탐색을 디지털 정보만으로 처리할 수 있는 작업에서는 OCR 모델을 로딩하지 않는다. 실제 이미지 판독이 필요한 첫 작업에만 Worker를 지연 로딩하고 같은 작업 묶음에서 재사용한다. 해당 OCR 작업이 끝나면 작업 전용 Worker를 종료하여 점유 자원을 해제한다. 다른 업무나 다른 작업의 프로세스를 종료하지 않는다.

**RUN-02 — 단계적·범위 제한 판독.** 기본은 로컬 정찰, 필요한 영역 재탐색, 확정 Fence 안의 판독이다. 로컬이 불확실하면 승인된 AI를 위치 탐색 또는 제한된 값 판독에 사용한다. 정찰과 정밀 판독의 역할은 분리하되 검증 가능한 중간 자료와 로딩된 엔진을 재사용할 수 있다. 문제 행만으로 관계가 확인되지 않으면 같은 Fence 안의 필요한 표제·연속 행을 포함하고, 과도한 Crop으로 매칭 근거를 잘라내지 않는다.

**RUN-03 — 시간·호출·자원 상한.** 문서·단계별 재시도 횟수, 누적 처리시간, 외부 호출 비용 및 자원 상한을 둔다. 같은 실패를 무제한 반복하지 않는다. 상한 초과·취소·Worker 초기화 실패·프로세스 장애는 확보한 결과와 실패 지점을 보존하고 후속 파일에 전파되지 않도록 한다. 세부 상한은 기준선 실측과 운영 승인 후 설정한다.

**RUN-04 — 입력과 작업의 격리.** 다른 PDF·다른 항·이전 AI 대화의 정보가 현재 값 판독에 섞이지 않도록 실행 문맥을 분리한다. 캐시·판독 자료 재사용은 원본 해시, 항·영역, 관련 버전·설정의 호환성을 확인한 경우만 허용한다. 처리 도중 실패·취소된 결과를 정상 완료 캐시로 저장하거나 미확정 후보를 확정값으로 승격하지 않는다.

특정 OCR 제품·AI 모델·해상도·점수 가중치·임계값은 영구 업무 규칙으로 고정하지 않는다. TRD에서는 승인한 로컬 우선·제한적 AI 보조·배치 한정 OCR 재사용 원칙을 만족하는 최소 복잡도의 구성을 선택한다.

## 12. 최종 판정과 문서 전체 완전성

**VAL-01 — 값 결정과 검증 권한.** 후보를 최종 판독 결과로 정리하는 책임은 한 곳으로 모은다. Validator는 값을 수정하지 않고 품질을 판정한다. GUI·내보내기·KOSHA/MES가 판독값을 다시 자동 결정하거나 예외 목록으로 교체하지 않는다. 인간 교정은 별도 후단 절차다.

**VAL-02 — 증거 우선.** 특정 파서·OCR·AI의 고정 서열, 과반수 투표, 체크디지트 통과, 모델의 자신감만으로 후보를 확정하지 않는다. 같은 원본에 대한 복수 판독의 일치는 보조 근거이며 오류가 독립적이라는 보장은 없다. 구조·문자·단위·매칭 근거가 충돌하면 허용된 한도에서 재확인하고 해결되지 않으면 REVIEW_REQUIRED로 남긴다.

**VAL-03 — 문서 전체 PASS.** 전체 PASS는 1항 제품명과 3항 대상 기재를 끝까지 처리하고, 필요한 Fence·근거·매칭이 확인되며, 미해결 후보·판독 불가 영역·누락 의심이 없을 때만 허용한다. CAS 두 개를 정확히 읽어도 나머지 영역이 미확인이라면 전체 PASS가 아니다. 완전성 확인은 무오류의 절대 증명이 아니라 자동 확정에 필요한 검사 조건이며, 실제 누락 성능은 정답 자료군으로 별도 검증한다.

**VAL-04 — 품질·실행·범위별 상태.** PASS/REVIEW_REQUIRED는 품질 판정이다. 완료·부분 처리·시간 초과·취소·실행 오류는 실행 상태로 별도 관리한다. 제품명·각 CAS 기재·함유량·항·문서 전체의 상태를 구분한다. 정상적인 추출 대상 0건, 미기재, 판독 실패, 미완료를 같은 빈 결과로 표시하지 않는다. 실행 불가 결과에 정상 PASS를 부여하지 않는다.

### 문서 전체 판정 예시

| 상황 | 문서 전체 처리 |
|---|---|
| 제품명과 3항의 모든 대상 기재 확인 | 자동 PASS 가능 |
| 제품명 정상, 3항 전체에 CAS 기재가 실제 없음 | 정상적인 대상 0건으로 완료 가능 |
| 일부 CAS 정확, 나머지 영역 미확인 | 부분 결과 보존 및 REVIEW |
| CAS 정상, 대응 함유량 실제 미기재 확인 | CAS 유지; 미기재만으로 REVIEW 강제하지 않음 |
| 제품명 미확인, 3항 정상 | 3항 보존; 문서 전체 REVIEW |
| 수치 100% 초과이나 원문·매칭 명확 | 추출 PASS 가능; 별도 경고 |
| Fence 미확정 또는 실행 중단 | 정상 0건으로 간주하지 않음 |

## 13. 사용자 보완·승인·재처리

**REV-01 — 세 층의 분리.** Machine Result, User Correction, 업무용 Approved Result를 구분한다. 사용자 수정은 원본을 확인하는 후단 기능에서 수행하며, 변경 필드·이전값·수정값·수정 시점·원본 연결을 추적할 수 있어야 한다. 기계 결과는 원형 보존한다. 수정하지 않은 필드가 불필요하게 바뀌지 않아야 한다.

**REV-02 — 재추출 보호.** 재추출은 새 Machine Result를 만든다. 기존 교정값·승인 결과를 자동 덮어쓰지 않고 차이를 제시하여 사용자가 적용 여부를 결정한다. 같은 파일명의 원본 해시가 바뀌면 이전 교정을 자동 적용하지 않는다. 화면 초기화·캐시 정리·엔진 새로고침이 교정 이력·승인 결과·Golden·원본을 삭제하는 동작과 섞이지 않게 한다.

**REV-03 — 자동 확정과 인간 확인 이력.** 자동 PASS는 후속 업무 사용 자격을 줄 수 있지만 사람 확인 완료로 기록하지 않는다. 사람 확인·수정이 완료된 경우 해당 이력을 별도로 남긴다. 수정 내용을 저장한 것과 미해결 사항까지 승인한 것은 구분하며, 부분 수정만으로 나머지 REVIEW를 자동 해제하지 않는다.

**REV-04 — 검토 결과의 사용 경계.** 미승인 REVIEW 결과는 검토 화면·검토용 내보내기에 보존할 수 있으나 확정된 정상 결과처럼 업무용 결과에 섞지 않는다. 파일 묶음 중 정상 문서의 저장을 다른 문서의 REVIEW 때문에 불필요하게 막지 않되 제외·보류된 문서를 명시한다. 일부 필드·성분만 사용하는 추가 운영 정책은 승인 없이 자동 도입하지 않는다.

## 14. KOSHA/MES 후단 보강

**KOS-01 — 이번 범위의 성능 검증과 비동기 분리.** KOSHA 조회 성능 재검증과 비동기 후단 분리는 이번 재기준화의 필수 범위다. 실제 요청 수, 캐시 적중, 호출 간격 대기, 네트워크 응답, 재시도, 로컬 저장 및 화면 반영 시간을 구분해 측정한다. 기존 UI에서 이미 분리된 부분은 활용하고, 남은 종속 대기를 제거한다. KOSHA 지연이 추출 결과 표시·사용자 검토·기존에 보강정보 없이 가능한 기능을 불필요하게 막지 않아야 한다.

**KOS-02 — 원문 불변과 실패의 의미.** 보강은 확정된 CAS를 근거로 물질명·규제 등 기존 업무 정보를 붙이는 별도 결과다. 제품명·CAS·함유량을 변경하지 않는다. 통신 실패·조회 중·자료 없음·캐시 만료·갱신 실패·정상 조회를 구분하고, 확인하지 못한 규제정보를 False 또는 비대상으로 확정하지 않는다. 늦게 도착한 응답은 원본·대상 CAS·결과 개정 식별자가 맞는 경우만 적용한다.

**KOS-03 — 호출 최소화와 기존 의미 보존.** 같은 CAS의 동일 조회는 기존 캐시·요청 묶음 내 재사용으로 중복을 줄일 수 있다. 이는 원문 CAS 기재의 합산·중복 제거와 다른 기능이다. 최신성·출처·조회 범위가 호환되는 캐시만 사용하며 상세 정책은 공식 API와 사용 계정의 확인 결과에 맞춘다. 속도 개선을 이유로 기존 필수 조회 정보나 MES 매핑 의미를 생략하지 않는다. 전체 로컬 마스터나 2·8항 확장은 이번 작업에 추가하지 않는다.

보강이 완료되지 않아도 추출은 완료될 수 있다. 다만 보강정보가 필수인 후속 업무의 완료 여부는 별도로 판정한다. 부분 보강을 완전한 규제 검증 완료로 표시하지 않는다.

## 15. 기존 GUI·저장·업무 기능 보존

**UX-01 — 기존 기능 우선.** 사용자 보완은 기존 GUI 활용을 우선한다. 파일 입력·목록 관리, 추출·중지, 원본 확인, 결과 수정, 기존 KOSHA/MES 연계, 엑셀 매핑·저장, 진단 확인 등 실제 운영 중인 기능의 보존 목록을 이행 시작 시 확인한다. 미사용·실험 기능을 모두 영구 보존하라는 뜻은 아니며, 제거·축소 대상은 근거와 사용자 승인을 구분한다.

**UX-02 — 표시와 내보내기의 일치.** 화면의 수정은 구조화된 교정·승인 데이터에 반영하고, 업무용 내보내기는 그 데이터를 기준으로 한다. 화면 문자열을 다시 파싱하여 새로운 정답을 만들지 않는다. CAS 순서·반복 기재·공통 함유량·부등호·단위·미기재 표시와 기존 승인된 엑셀 열 매핑·출력 형식을 보존한다. 셀의 날짜·수식 등 자동 해석 때문에 원래 문자열 의미가 바뀌지 않아야 한다.

**UX-03 — 저장영역과 정리의 분리.** 원본·기계 결과·교정·승인 결과·Golden·실행 캐시·진단 로그를 목적에 맞게 구분한다. 임시파일 정리는 원본이나 업무 데이터 삭제가 아니다. 보존 정책에 따른 삭제는 대상과 영향을 알 수 있게 하고, 승인 데이터의 복구 가능성을 검증한다. 보존 기간은 별도 운영 설정으로 확정한다.

**NFR-01 — 지표의 공동 보고.** 정확도와 처리량·REVIEW·비용을 따로 유리하게 골라 보고하지 않는다. 아래 지표를 같은 평가 집합과 실행 조건에 대해 함께 보고하며 디지털·스캔·혼합 대상 영역, 최초 로딩·재사용 상태를 나눈다.

정확도 평가의 “누락”은 고유 CAS 개수가 아니라 원문 기재를 기준으로 한다. 자료 수가 적어 신뢰하기 어려운 세부군은 표본 수와 한계를 함께 표시하며, 테스트 내 무위반을 모든 실무 문서의 무오류 보장으로 표현하지 않는다.

## 17. Golden v2와 검증 자료

**GLD-01 — 기존 자산의 지위.** 기존 Golden·실제 PDF·과거 실패 기록은 재검증 후보로 보존한다. 기존 케이스 수·ID·해시·승인 표시를 그대로 신뢰하지 않고 중복·누락·원본 대응·정답 근거를 확인한다. 정답 재검증 전의 자료를 새 절대 기준으로 삼지 않는다.

**GLD-02 — 사람 승인과 원장 무결성.** 값 정답은 사람이 원본 1항·3항을 직접 확인하고 승인한 자료로 정한다. 원본 해시, 제품명 근거, 순서 있는 CAS 기재, 공통 함유량 관계, 최초 원문 표기·단위·정답 상태·실제 페이지, 승인 시점·방식·수정 사유를 추적할 수 있어야 한다. 개인 실명 수집은 필수로 하지 않되 승인 행위와 권한 있는 검토 이력은 식별 가능해야 한다. 중복 ID·원본 불일치·필수 자산 누락은 검증을 막는 오류다.

**GLD-03 — 평가 자료의 분리.** 값 정답 사례군과 안전한 REVIEW·실패 동작 사례군을 구분한다. 개발·규칙 조정에 반복 사용한 회귀 자료와 별도로 최종 현장 평가 자료를 확보하고 버전을 고정한다. 최종 평가 자료를 개선에 사용한 뒤에는 다시 미사용 자료인 것처럼 보고하지 않는다. 혼합형·다중페이지·복수 CAS·CAS 없는 행·흐린 기호·경계 실패 등 핵심 실패 유형을 포함한다.

**GLD-04 — 변경과 적합성.** 엔진 결과에 맞추기 위해 Golden을 수정하지 않는다. 사람의 원본 재확인, 변경 사유, 재승인을 거친다. 사용자 운영 교정은 자동으로 Golden이 되지 않는다. PDF 해시가 달라지면 해당 실행과 이전 Golden의 대응을 차단하되, 옛 원본에 대해 승인된 Golden의 역사적 유효성까지 삭제하지 않는다. 새 원본은 새 검토 대상으로 관리한다.

Golden 검증기는 값뿐 아니라 순서·중복 기재·상태·출처·음성 사례를 확인해야 한다. 원본 1항·3항은 유지하고 다른 항의 CAS·숫자만 바꾼 검증용 변형에서 핵심 추출값과 Pair 결과가 바뀌지 않는지도 검사한다. 변형 자료는 원본을 덮어쓰지 않는 별도 테스트 자산이다.

## 18. 보안·외부 전송·진단 자료

**SEC-01 — 승인된 전송 경계.** 승인된 외부 판독 제공자와 전송 정책만 사용한다. 값 판독에는 허용된 Fence·문제 영역만 전송하고, 경계 탐색에는 필요한 페이지 범위를 사용한다. 파일 경로·인증정보·무관한 자료를 불필요하게 첨부하지 않는다. 외부 전송이 금지된 자료는 다른 제공자로 자동 우회하지 않고 로컬 처리 또는 수동 검토 대상으로 남긴다.

**SEC-02 — 문서 내용은 명령이 아님.** MSDS 안의 문장·이미지·메타데이터는 판독 대상이다. 문서 안의 지시문으로 Fence, 판독 목표, 모델 라우팅, 외부 전송 또는 데이터 보존 정책을 변경하지 못하게 한다. AI 반환값은 입력 범위·형식·근거 검사를 통과해야 하며 외부 작업 실행 명령으로 사용하지 않는다.

**SEC-03 — 로그와 공유.** 인증키·토큰을 로그·보고서·Golden에 기록하지 않는다. 원문 이미지·진단 공유는 사용자가 선택한 범위와 승인된 목적에 한정하며 자동 외부 공개를 하지 않는다. 진단 모드와 보존 기간을 업무 원본·교정 데이터의 보존과 구분한다. 전송 정책 및 보존 설정의 구체값은 운영 설정으로 확정한다.

## 19. 기존 V6 보존과 점진 전환

**MIG-01 — 사실에 근거한 기준선.** 이행 시작 시 실제 운영 커밋·브랜치·로컬 변경·실행환경·캐시·교정 데이터·기존 테스트의 통과/실패 상태를 확인한다. GitHub 코드가 로컬 운영 최신 버전이라고 가정하지 않는다. 기존 V6는 비교용 기준선이며 전체가 검증되었다거나 정답의 최종 권위라고 표현하지 않는다.

**MIG-02 — 단계적 교체와 차이 분류.** 전면 재작성·일괄 삭제를 기본 방식으로 삼지 않는다. 기존 구현을 보존하고 경계를 만들어 단계적으로 교체한다. 신구 결과 차이는 승인된 정책 변경, 기존 오류 수정, 신규 회귀, 원본/Golden 재검토 필요로 구분한다. 정책 변경으로 의도적으로 달라진 결과를 무조건 회귀로 판정하지 않는다. 구조 이동과 결과 의미 변경은 가능한 한 별도 변경 단위로 검증한다.

**MIG-03 — 어댑터의 한계.** 기존 결과를 새 계약으로 옮기는 호환 계층은 알 수 없는 출처·페이지·Fence·원문값을 꾸며 채우지 않는다. 복원할 수 없는 필드는 미확인으로 남기고 새 계약의 자동 PASS로 승격하지 않는다. 기존 경로와 새 경로의 동등성은 승인 정책과 실제 근거를 기준으로 비교한다.

**MIG-04 — 안전한 검증과 전환.** 결정적인 로컬·계약 회귀 테스트와 실제 OCR·AI·KOSHA 통합 평가를 분리한다. 신구 동시 실행은 비교 목적의 승인된 자료·호출 예산·격리 환경에서 수행하고, 운영 문서마다 무조건 두 엔진을 호출하지 않는다. 검증기는 운영 코드·원본·교정·Golden을 수정하지 않으며 필요한 쓰기는 작업용 출력에 제한한다. 운영 전환과 기존 경로 폐기는 별도 승인 후 수행하고, 결과 보존과 복구 가능성을 확인한다.

## 21. 완료 Gate

**Gate 0 — 요구 기준 승인.** PRD v1.1 승인과 요구사항 ID 확정. 보류 과제와 이번 범위를 구분하고 문서 우선순위를 합의한다.

**Gate 1 — 착수 기준선 확인.** 실제 운영 버전·환경·사용 기능·데이터 보존 상태, 기존 Golden의 원본 대응과 현재 통과/실패를 확인한다. 확인하지 못한 부분은 미확인으로 기록한다.

**Gate 2 — TRD 및 검증 계획 승인.** 모든 PRD 요구사항을 기술 설계와 테스트에 연결한다. 세부 데이터 계약·경계 격리·사용자 교정·비동기 응답 적용·Worker lifecycle·신구 비교·복구 방법을 명시한다. 작업지시서는 이 승인 이후 별도로 작성한다.

**Gate 3 — 정책·회귀 검증.** 승인된 Golden v2의 정확값 및 검토 필요 시나리오를 통과하고, 입력 범위 위반·교정값 손실·CAS 없는 행 전이·정상 0건 오판 등 핵심 금지 동작이 없음을 검증한다. 필수 자료가 빠지거나 테스트가 실행되지 않았으면 PASS가 아니라 검증 미완료다.

**Gate 4 — 운영 수용성 검증.** 실제 현장 최종 자료군과 운영 환경에서 승인된 품질·자동 처리 비율·시간·비용·자원 기준을 충족한다. 기존 GUI/엑셀/보강 기능, KOSHA 지연·실패, 재처리·재시작·취소·복구를 검증한다.

**Gate 5 — 운영 전환 승인.** 위 결과와 남은 위험을 사용자가 검토하여 전환을 승인한다. 그 전까지 기존 운영 경로를 자동 삭제하지 않는다. 작업 전용 자원은 결과 보존 후 정리한다.

## 22. TRD에서 구체화할 항목

이번 문서로 추출 범위·CAS/함유량 규칙·원문 보존·Fence·사용자 보완·KOSHA 범위는 다시 열어두지 않는다. 아래는 업무 방향을 재논의할 사안이 아니라 기술 설계 또는 실측 후 확정할 값이다.

| 항목 | 구체화 내용 | 확정 시점 |
|---|---|---|
| 상세 계약 | 필드명, 기재 식별자, 근거 좌표, 상태 전이, 버전 연결 | TRD 승인 |
| 실행 구조 | 모듈 경계, Worker 수명, 작업 격리, 호환 어댑터, 중복 판독 자료 재사용 | TRD 승인 |
| 판독 설정 | 실제 가용 모델, 로컬 확정 조건의 검증 방법, 해상도·재시도·예산 설정 | 벤치마크 계획 및 실행 설정 승인 |
| 수용 수치 | 품질·자동 처리·시간·비용·자원 목표, 평가 자료군과 표본 수 | 기준선 실측 후, Gate 4 이전 |
| 후단 운영 | 현재 API/계정 조건, 캐시 최신성, 요청 제한·취소·응답 개정 적용 | TRD 및 KOSHA 성능 검증 |
| 보존·전송 | 원본·교정·로그 보존 기간, 외부 제공자·전송 제한과 공유 범위 | 운영 설정 승인 |

PRD 승인만으로 미정 수치를 임의 확정하거나 운영 전환을 허용하지 않는다. 반대로 수치 실측 전이라는 이유로 승인된 업무 정책을 계속 변경하지 않는다.

## 24. 작성 근거와 최종 원칙

작성 근거는 이 대화의 사용자 설명·승인된 Stage 1~3 정책, 작성된 PRD v1.0, 직전 PRD 보완 검토다. 외부 API의 현행 정책·계정 한도·현재 저장소 상태·모델 성능을 이번 문서에서 새로 검증한 것은 아니다. 실제 구현 상태와 정량 기준은 관련 Gate의 확인 결과로 기록한다.

최상위 원칙은 다음과 같다.

**정답 출처는 1항과 3항으로 제한한다. 판독 수단과 업무 기준을 분리한다. 원본·판독값·교정값을 보존한다. 일부를 맞혔다는 이유로 전체가 맞았다고 선언하지 않는다. 모르는 값을 채우지 않되, 자동 처리 비율과 비용도 함께 검증한다. 후단 시스템은 추출 사실을 자동으로 다시 쓰지 않는다.**

문서 승인 이후의 다음 단계는 **TRD v1.0 작성·승인**이며, 실제 실행은 그다음의 버전·차수 명시 작업지시서로 분리한다.
