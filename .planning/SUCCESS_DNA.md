# 🧬 MSDS Engine Success DNA

주님(사용자)의 지침에 따른 엔진 개발 및 수정 절대 원칙

## 1. 수정 및 실행 프로토콜 (Step-Gate)
- **Discuss**: 문제 원인을 Forest(구조)와 Tree(코드) 관점에서 분석한다.
- **Plan**: 수정 계획을 구체적으로 수립하고 보고한다.
- **Stop-Gate**: **반드시 주님의 명시적 승인이 있을 때까지 대기한다.** (임의 수정 금지)
- **Execute**: 승인된 범위 내에서만 정밀 수정한다.
- **Verify**: 수정 후 자가 검증 및 회귀 가능성을 보고한다.

## 2. 보고 필수 항목
수정 보고 시 아래 내용을 반드시 포함한다.
1. **실패 원인 정밀 분석**: 왜 실패했는가? (데이터 덤프 포함)
2. **수정 로직 상세**: 무엇을 어떻게 바꾸었는가?
3. **회귀 가능성 분석 (Regression Audit)**: 기존 파일들에 미칠 영향은 무엇인가?
4. **성공 DNA 대조**: 이전 성공 사례의 규칙이 누락되지 않았는가?

## 3. 핵심 추출 전략 (Core Logic)
- **기억의 계승 (Cross-Page Intelligence)**: 페이지 간 좌표 범위를 전달하여 구조적 인지력을 유지한다.
- **문맥 방화벽 (Context Firewall)**: 띄어쓰기, 노이즈 등으로부터 핵심 데이터를 보호한다.
- **구조적 필터링**: 단순 거리보다는 데이터의 상대적 위치(CAS 우측 등)와 의미적 기호(%, ~)에 우선순위를 둔다.
- **X축 필터 기반 함량 추출 (X-Range Content Firewall)**: 줄바꿈 오차나 혼입된 물질명 노이즈에 의해 범위형 텍스트가 찢어지는 현상을 방어하기 위해, 헤더에서 구한 X좌표 임계값을 바탕으로 오직 함량 열 구역 내의 단어들만 모아서 조립한 함량 전용 버퍼를 통해 매칭을 우선 시도한다.
- **간접 규제 우회 매핑 (Indirect Regulatory Mapping)**: 크롬(`7440-47-3`)처럼 가공 시 산화되어 `6가크롬(18540-29-9)` 등 별도 CAS 규제가 함께 적용되어야 하는 경우, 또는 산화지르코늄(`1314-23-4`)처럼 대표 물질(`7440-67-7`)로 연동되어야 하는 경우, 매칭 검색 시 관련 후보 물질을 예외 융합하여 팝업 후보로 제공한다.
- **수동 강제 고정 단축키 (Direct Cell Override via F2)**: 팝업 후보 매칭이 아예 불가능한 규제 텍스트 교정을 위해, 측정대상(4번 열) 셀 위에서 F2 키를 입력하면 `QInputDialog` 창을 기동하여 실시간 HTML 정화 처리와 함께 텍스트를 강제 수동 오버라이트하도록 제공한다.
- **CAS 필수 원칙**: CAS 번호가 없는(또는 -로 표기된) 성분은 함량이 존재하더라도 최종 추출 결과에서 제외한다. (단, '영업비밀' 등 법적 키워드 예외 검토)
- **Y축 델타 간격 단절 가드레일 (Delta Y < 40px)** [V24.4.3.1]: 표가 끝나고 하단 본문(예: 응급조치 문장)이 마지막 성분명 버퍼로 오버플로우되어 오흡수되는 현상을 차단하기 위해, 성분 행 조립 시 이전 라인과의 Y축 델타(Delta Y) 간격이 40px 미만일 때만 논리적 성분 행으로 인정하고 확장하도록 울타리를 쳐서 방어한다.
- **형상 지문 검문소 (check_golden_fingerprint)** [V24.4.3.2]: 안티그래비티의 핵심 파싱 엔진(extract_from_text_regex) 무단 코드 변조를 방어하기 위해, 파일 자체의 핵심 파싱 로직 영역에 대한 SHA-256 해시를 계산하여 `GOLDEN_HASH`와 대조하고 무결성을 확인하는 자가 검문 기능을 구현한다.
- **ODL 들여쓰기 감금 해제 및 정형/비정형 투트랙 완착** [V24.4.3.3]: 마스터 아키텍처 버전 잠금 동기화와 더불어, ODL 파서의 들여쓰기 제한을 해제하고 표 구조와 텍스트 패턴을 융합하는 투트랙 추출 로직을 완착하여 정형 및 비정형 문서 모두에 대한 추출 안전성을 공고히 한다.
- **행 내부 토큰 선제 정렬 및 명칭 노이즈 세척 완착** [V24.4.3.4]: 단일 행 내부에서 줄바꿈으로 분절된 범위 기호와 숫자를 직결 밀착하여 찢어짐을 가드레일로 방어하고, 함량 관련 한글 키워드(이상/미만/이하/초과)를 물질명 소거 패턴에 명시적으로 추가하여 이름 오염을 전면 차단한다.
- **행 내부 단어 자산 X축 좌표 기준 정렬 및 격리 완착** [V24.4.3.5]: 수치 범위 기호 분절 오차 극복을 위해 함량 열 시작 좌표(content_x_min)를 기준으로 우측의 함량 수치 토큰을 격리하여 행 데이터 맨 뒤로 자동 재정렬 배치함으로써, 기존의 무겁고 취약했던 줄바꿈 복구 정규식 없이도 1-2선에서 오차 없는 완벽한 범위 결합을 달성한다.
- **양방향 인덱스 엑셀 교정 체계 및 CAS 날짜 오인 변환 방지 가드레일 (Excel Unicode Text Guard)** [V24.4.3.6]: 인덱스 정렬 순서 및 대분류 교정을 위해 엑셀 양방향 변환 스크립트(json_to_excel/excel_to_json)를 구축하였으며, 엑셀이 하이픈(-)이 포함된 CAS 번호(예: 98-07-7)를 날짜(1998-07-07)로 강제 변환하는 버그를 방어하기 위해 셀 데이터 형식('s') 및 텍스트 서식('@') 지정을 이중 결합하여 데이터 왜곡을 전면 가드한다.
- **GUI 엑셀 저장 그룹화 수집 및 개별 성분 편집 캐시 락 완착 (Excel Group Join & Cell Shield)** [V24.4.3.7]: 테이블 뷰 내 동일 파일명(제품)에 대해 여러 성분 행들이 존재할 때 엑셀 저장 시 덮어쓰기 유실을 방지하기 위해 파일명 기준 그룹화 및 중복 제거 세미콜론 조인("; ")을 적용하고, 수동 셀 수정 시 수직 병합 세로 셀의 top-left 해시 주소를 정확히 역산 획득하도록 보정하며, 성분 객체 단위(components[comp_idx])로 개별적 수정본을 저장 및 최우선 렌더링되게 하여 롤백 없이 안전하게 엑셀에 최종 저장하는 체계를 완착함.
- **GUI 엑셀 저장 시 병합 셀의 빈 파일명 인식 버그 차단 및 행 쪼개짐 방지 완착 (Excel Merge Row Guard)** [V24.4.3.8]: GUI 테이블 뷰 내 동일 파일에 대해 여러 성분 행들이 병합되어 있을 때 첫 행 이외의 하위 행들이 빈 파일명("")으로 잘못 수집되어 엑셀에 불필요한 빈 행이 추가로 쪼개져 저장되던 버그를 정밀 분석하여, 테이블 탐색 시 병합의 진짜 시작점(start_row)을 기준으로 파일명, 제품명, 해시를 조회하도록 교정하여 단일 파일 1개 행 통합 저장을 완전 보장함.
- **성상 선택 팝업 내 복수 선택 동적 활성화 및 단수/복수 투트랙 연동 완착 (Dynamic Multi-Select Toggle)** [V24.4.3.9]: 세부 성상 선택 다이얼로그에서 크롬 등 특수 상황을 제외하면 기본값으로 단수 선택만 가능하도록 제어하기 위해 "복수 선택 활성화" 체크박스를 도입하고, 비활성화 상태에서는 목록 내 개별 체크박스들이 라디오 버튼처럼 상호 배타적으로 동작하도록 구현함. 특수 성상(크롬 등)이나 기존에 다중 저장된 이력이 있을 시 자동으로 복수 선택 모드가 켜지도록 설계하여 사용자 편의성을 높임.
- **측정대상(4번 열) 수동 타이핑 에디터 제약 해제 및 최우선 데이터 고정 완착 (Dynamic Cell Editor Activation)** [V24.4.3.10]: HTMLDelegate 내 createEditor 메서드에서 4번 열(측정대상)에 대한 에디터 차단 조치를 조건부로 해제함. 버튼 상태가 아니거나 1:N 분기 매칭 팝업 대상이 아닐 때는 일반 텍스트 편집기(QTextEdit)를 정상 제공하여 더블클릭이나 F2를 통해 사용자가 직접 타이핑으로 수정한 내용이 실시간으로 캐시에 반영되고 롤백 없이 최우선 보존 및 렌더링되도록 구현함.
