# 구현 계획서: MES 마스터 데이터 자동 매핑 및 측정대상 고도화

이 계획서는 MSDS 엔진에서 추출된 화학 성분을 `MES_MASTER_LOOKUP.json`의 마스터 데이터와 자동으로 매핑하고, 측정대상 필드를 생성하는 기능의 구현 방안을 담고 있습니다.

## 1. 개요
추출된 성분(CAS 번호)이 마스터 데이터에 직접 존재하지 않더라도, KOSHA API를 통해 해당 물질의 분류(예: 6가크롬 수용성)를 파악하여 측정대상 명칭을 자동으로 매핑합니다.

## 2. 주요 원칙 및 제약 조건
- **함유량 필터링**: 함유량이 **1% 미만**인 성분은 측정대상 매핑에서 제외합니다. (단, 추출 결과에는 남겨두되 '측정대상' 필드에만 포함하지 않음)
- **KOSHA API 연동**: CAS 번호로 마스터 데이터 매핑 실패 시, KOSHA API의 '8. 노출방지 및 개인보호구' 항목을 조회하여 카테고리명을 식별합니다.
- **포리스트-트리-포리스트 (FTF) 준수**: `msds_engine_v5.py` 수술 시 전체 분석 후 정밀 수정을 진행하며, 기존 정규표현식 로직의 퇴행(Regression)을 방지합니다.

## 3. 상세 구현 단계

### Phase 1: 매핑 서비스 로직 설계 (`MappingService`)
- [ ] `KoshaAPIClient` 확장: '국내규정' 텍스트에서 카테고리 명칭(예: "크롬(6가, 수용성)")을 정밀하게 추출하는 전용 메서드 추가.
- [ ] `MES_MASTER_LOOKUP.json` 인덱스 고도화:
    - CAS 번호 인덱스 (기존)
    - 물질명/상용명/영문명 기반 유사도 검색 인덱스 (추가)
- [ ] 매핑 우선순위 정의:
    1. CAS 일치 (Perfect Match)
    2. KOSHA 카테고리명 <-> MES 물질명 일치 (Group Match)
    3. TWA 및 물질군 기반 추론 (Heuristic Match)

### Phase 2: 엔진 통합 (`msds_engine_v5.py`)
- [ ] `process_pdf` 함수 내 측정대상 생성 로직 수정:
    - `refined_comps` 순회 시 함유량 체크 (`_normalize_single_content` 결과값 파싱).
    - 1% 이상인 성분에 대해서만 `MappingService` 호출.
- [ ] `target_substances` (측정대상) 필드 업데이트:
    - 매핑된 마스터 물질명들을 세미콜론(`;`)으로 구분하여 저장.

### Phase 3: 검증 및 테스트 (`Verification`)
- [ ] **성공 DNA 대조**: 이전 버전에서 성공했던 정규표현식 및 파싱 로직과의 정합성 확인.
- [ ] **테스트 케이스 실행**:
    - CAS 7778-50-9 (중크롬산 칼륨) -> '6가크롬(수용성)' 매핑 확인.
    - 0.5% 성분 -> 매핑 제외 확인.
    - 5% 성분 -> 매핑 포함 확인.

## 4. 기대 결과
사용자가 MSDS를 업로드하면 제품명과 구성성분뿐만 아니라, 측정 시 사용해야 할 **표준 측정대상 명칭**이 자동으로 출력되어 작업 효율성이 극대화됩니다.
