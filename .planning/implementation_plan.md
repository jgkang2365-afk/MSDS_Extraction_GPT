# [GSD2] V17.3.1.16: 고분자 추출 무결성 및 ODL 복구 계획

## 1. 개요
013_아이생각수성내부프로 MSDS에서 발생하는 1페이지 성분(고분자 포함 8건) 추출 실패 문제를 해결합니다. 기존 V18 기반의 낡은 계획을 폐기하고, 현재 V17 엔진의 ODL 및 Regex 보조장치를 정밀 교정합니다.

## 2. 작업 상세 (FTF 프로토콜)

### [Forest] 사전 분석
- **현상**: ODL이 1페이지 메인 테이블을 인식하지 못함 (ODL Page 0/1 데이터 부재).
- **원인**: 1페이지 상단의 제품 정보 표와 성분 표가 너무 밀착되어 있어 ODL이 헤더를 오인식할 가능성 농후.
- **영향**: Regex 보조장치가 100% 부담을 지게 되나, 고분자처럼 이름이 길어 여러 줄로 쪼개진 경우 함량 매핑에 실패함.

### [Tree] 정밀 수정 단계

#### 🛠️ Task 1: ODL 테이블 헤더 인식 유연화 (`msds_engine_v5.py`)
- Section 3의 시작 지점을 찾는 정규식을 보강하여, 1페이지 하단이나 2페이지 상단에 걸쳐 있는 테이블을 놓치지 않게 함.
- 테이블 병합 시 CAS 번호가 있는 행은 무조건 '유효 행'으로 간주하도록 ODL 파서 규칙 완화.

#### 🛠️ Task 2: 고분자 전용 '논리적 행 결합' 엔진 (`extract_from_text_regex`)
- 단순 Proximity Search가 아닌, **물질명-CAS-함량**을 하나의 튜플로 인식하는 로직 구현.
- CAS 번호 발견 시, 위/아래 5줄 내의 텍스트를 합쳐서 `polymer` 키워드가 포함된 긴 이름을 완성하고 함량을 연결.

#### 🛠️ Task 3: OCR 노이즈(맊/핚) 대응 코드 이식
- `.planning/TROUBLESHOOTING_OCR_BUG.md`에 기록된 성공 사례를 적용.
- `미만` -> `미[만맊먄]`, `이하` -> `이[하핚]` 정규식으로 부등호 유실 방지.
